# 개인 웹사이트 1차 버전 개발 계획

작성일: 2026-10-23

## 1. 목표

구조기술사 개인이 로컬 PC에서 쓰는 Next.js 웹사이트를 만든다. 사이트는 여러 개인용 웹앱을 담는 틀이고, 왼쪽 사이드바에 앱 목록이 있다. 이번 버전에서는 첫 번째 앱인 **업무 관리(개인 task 관리)** 를 완성한다.

완료 기준: `npm run dev` 실행 → 브라우저에서 접속 → 샘플 데이터가 들어 있는 세 화면(목록, 월별 달력, 간트차트)을 보고, 프로젝트와 task를 추가·수정·삭제할 수 있다.

## 2. 범위

### 이번 버전 (v0.1)

- 사이트 공통 틀: 왼쪽 사이드바(앱 목록), 홈 화면(앱 카드 + 오늘의 업무 요약)
- 사이드바의 미래 앱 5종은 비활성 "예정" 항목으로만 표시: 3D 모델 뷰어, 2D CAD 뷰어, 구조해석 FEM 뷰어, 문서(PDF) 뷰어, PPT 뷰어
- 업무 관리 앱
  - 프로젝트 추가·수정·삭제 (이름, 색상, 발주처, 메모)
  - task 추가·수정·삭제 (제목, 프로젝트, 시작일, 마감일, 상태, 우선순위, 진행률, 메모)
  - 목록 화면: 프로젝트별 그룹 표, 빠른 입력 줄, 상태 바로 변경, 검색·상태 필터, 그룹 접기
  - 월별 달력: 여러 날에 걸친 task를 막대로 표시, 프로젝트 색 구분, 빈 날짜 클릭 시 해당 날짜로 새 task
  - 간트차트: 프로젝트별 그룹, 옅은 막대 = 프로젝트 전체 기간, 진한 막대 = task(진행률 표시), 오늘 선, 확대/축소(일·주·월)
  - 키보드 단축키: `N` 새 task, `Esc` 창 닫기
- 로컬 SQLite 저장, 로그인 없음
- 처음 실행 시 샘플 데이터 자동 입력 (구조설계, 정밀안전진단, 구조검토 프로젝트 3개)
- 라이트 테마(필수) + 다크 모드 전환(선택, 여유가 되면)

### 다음 버전 이후

- 뷰어 5종 실제 구현 (3D, 2D CAD, FEM, PDF, PPT)
- 간트차트에서 막대 끌어서 날짜 변경, 달력 드래그 이동
- 반복 업무, 하위 task(체크리스트), 첨부 파일
- 완료 프로젝트 보관(아카이브), 프로젝트 순서 변경
- 데이터 내보내기/가져오기(CSV, Excel), 백업
- 외부 접속·로그인·다중 사용자 (현재는 로컬 전용)

## 3. 기술 스택과 선택 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js 16 (App Router) + React 19 + TypeScript | 사용자가 Next.js로 결정함. 서버 컴포넌트에서 DB를 바로 읽을 수 있어 별도 백엔드가 필요 없음 |
| 스타일 | Tailwind CSS v4 + CSS 변수 디자인 토큰 | create-next-app 기본값. 토큰을 CSS 변수로 두면 다크 모드 확장이 쉬움 |
| DB | SQLite, Node 24 내장 `node:sqlite` | 별도 설치·네이티브 빌드가 없음(이 PC에는 C++ 빌드 도구가 없어 better-sqlite3 같은 네이티브 모듈은 위험). 설치 전에 동작을 확인함 (SQLite 3.53) |
| 데이터 접근 | 얇은 리포지토리 계층 + 직접 작성한 SQL (ORM 없음) | 테이블 2개뿐이라 ORM은 과함. Drizzle 등은 `node:sqlite` 지원이 불확실 |
| 쓰기 경로 | REST API 라우트 (`/api/projects`, `/api/tasks`) | 화면과 검증 스크립트(curl)가 같은 경로를 쓰므로 실제 동작을 그대로 시험할 수 있음 |
| 입력 검증 | zod | 서버에서 입력값을 한 곳에서 검증 |
| 아이콘 | lucide-react | 일관된 선 굵기의 SVG 아이콘 (이모지 아이콘 금지 원칙) |
| 글꼴 | Pretendard (npm 패키지로 로컬 포함) | Inter 기반 한글 UI 글꼴. 인터넷 없이도 동작. ui-ux-pro-max의 "Minimal Swiss(Inter)" + "Korean Modern" 권장을 한 글꼴로 충족 |
| 날짜 처리 | 직접 작성한 `YYYY-MM-DD` 문자열 유틸 | 시간대 문제를 피하려고 날짜만 다루고 UTC 기준으로 계산 |

## 4. 디자인 방향 (ui-ux-pro-max 데이터 기반)

- 제품 유형 "Productivity Tool": Flat Design + Micro-interactions, 명확한 위계와 기능적 색, 빠른 동작(150ms), 키보드 단축키 필수
- 스타일: Minimalism & Swiss Style + Flat Design. 그림자는 최소, 얇은 테두리, 격자 정렬
- 색상: "SaaS (General)" 팔레트 기반. 주색 `#2563EB`(신뢰감 있는 파랑), 배경 `#F8FAFC`, 글자 `#1E293B`, 보조 글자 `#475569`, 테두리 `#E2E8F0`, 삭제 `#DC2626`. 사이드바는 짙은 슬레이트(`#0F172A`)로 시안의 느낌 유지
- 상태 색: 예정 = 슬레이트 회색, 진행 = 파랑, 완료 = 초록. 색만으로 구분하지 않도록 글자 라벨 항상 표시
- 프로젝트 색: 대비가 충분한 8가지 프리셋 중 선택
- 접근성: 글자 대비 4.5:1 이상, 포커스 링 유지, 아이콘 버튼에 aria-label, 동작 줄이기(prefers-reduced-motion) 존중

## 5. 데이터 모델

### projects

| 열 | 형식 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| name | TEXT NOT NULL | 프로젝트명 |
| color | TEXT NOT NULL | `#RRGGBB` |
| client | TEXT | 발주처 (선택) |
| memo | TEXT | 메모 (선택) |
| sort_order | INTEGER | 표시 순서 |
| created_at / updated_at | TEXT | ISO 시각 |

프로젝트 기간은 따로 저장하지 않고 소속 task의 가장 이른 시작일 ~ 가장 늦은 마감일로 계산한다.

### tasks

| 열 | 형식 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| project_id | INTEGER NOT NULL FK → projects(id) ON DELETE CASCADE | 소속 프로젝트 |
| title | TEXT NOT NULL | 제목 |
| start_date | TEXT | `YYYY-MM-DD` (선택) |
| due_date | TEXT | `YYYY-MM-DD` (선택), 시작일 이후여야 함 |
| status | TEXT NOT NULL | `todo`(예정) / `doing`(진행) / `done`(완료) |
| priority | TEXT NOT NULL | `low`(낮음) / `normal`(보통) / `high`(높음) |
| progress | INTEGER NOT NULL | 0~100 (%) |
| memo | TEXT | 메모 |
| sort_order | INTEGER | 표시 순서 |
| created_at / updated_at | TEXT | ISO 시각 |

DB 파일: `data/personal-site.db` (환경변수 `DB_PATH`로 변경 가능, git에서 제외)

## 8. 결정/가정

사용자에게 확인받지 못한 채 정한 사항이다. 첫 검토 때 확인이 필요하다.

1. **task 필드**: 제안했던 6개(제목, 프로젝트, 시작일, 마감일, 상태, 메모)에 **우선순위(낮음/보통/높음)** 와 **진행률(%)** 을 추가했다. 진행률은 간트 막대 안에 진하게 표시된다.
2. **프로젝트 필드**: 이름, 색상 외에 **발주처**와 **메모**를 추가했다.
3. **모든 task는 프로젝트에 속한다** (프로젝트 없는 task 불가). 간트·달력을 프로젝트별로 나누기 위해서다. 개인 일은 "개인/기타" 같은 프로젝트를 만들어 쓰면 된다.
4. **프로젝트 기간은 소속 task에서 자동 계산**한다(가장 이른 시작일 ~ 가장 늦은 마감일). 계약 기간 같은 별도 기간 필드는 두지 않았다.
5. **프로젝트를 지우면 소속 task도 함께 지워진다.** 삭제 전에 몇 개가 지워지는지 확인 창을 띄운다.
6. **날짜가 하나만 있는 task**: 달력·간트에서 그 하루짜리로 표시한다. 날짜가 둘 다 없으면 목록에만 나오고 간트에는 "날짜 없음"으로 표시한다.
7. **상태와 진행률은 서로 독립**이다. 단, 편집 창에서 상태를 "완료"로 바꾸면 진행률을 100%로 맞춰 준다.
8. **쓰기는 REST API**로 한다(서버 액션 대신). 검증 스크립트로 같은 경로를 시험하기 위해서다.
9. **DB 위치**: 프로젝트 폴더 안 `data/personal-site.db`. git에는 올리지 않는다. 처음 실행할 때 비어 있으면 샘플 데이터를 넣는다. `npm run db:reset`으로 초기화할 수 있다.
10. **글꼴**: ui-ux-pro-max는 한글용으로 Noto Sans KR을 권하지만, 화면 밀도가 높은 업무 도구에는 Inter 기반인 Pretendard가 더 알맞다고 판단했다. 로컬 파일로 포함해 인터넷 없이도 동작한다.
11. **화면 너비**: PC 사용을 기본으로 한다. 좁은 화면에서는 사이드바를 접고 표·간트는 가로 스크롤한다. 휴대폰 최적화는 하지 않았다.
12. **주 시작 요일**: 달력은 일요일 시작(시안과 같음).
13. **한국 공휴일 표시는 하지 않는다** (주말만 색 구분).
14. **로컬 전용**이므로 인증·보안 장치는 두지 않았다. 외부에 공개하면 안 된다.
